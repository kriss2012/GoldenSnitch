# Test strategy
Pyramid: unit (percentiles, inverse metrics, history derivation, weight validation) → API/integration with an isolated temp SQLite DB seeded identically each test → manual UI checklist (below) → browser E2E (TASK-023, **not written**). Regression plan = the full pytest suite on every change (`scripts/quality_gate.sh`, ~1.3 s). Test data: the seed generator (RNG seed 1337) plus inline CSV fixtures; edge-case players are planted by name (`Kaito_Strike`: top K/D, weak decision; `Mira_Solace`: leadership missing; `Dax_Lowsample`: 7 matches).
Pass/fail: a test passes only when executed; evidence is the JUnit-derived `TEST_CASES.md`. Not covered: frontend automation, concurrency, large-file streaming, security scanners (no secret/dependency scan was run).
**Manual UI checklist (not yet executed):** Squads loads both titles; "Scout IGL" preselects roster/role; Run scouting renders table; Why panel shows weights and missing metrics; Compare with 3 ticks; Add → roster coverage 100%; Players filters; Import validate/ import with errors; empty and error messages visible.
